# Sealed SIM-development readonly runtime

`sim_readonly_runtime.launch` is disabled by default. Set `enabled:=true` and provide an **existing absolute directory with no symlink in any supplied path component** as `artifact_root`. Launch passes validated command-line arguments directly to the node; it does not use ROS parameters.

The runtime creates one fresh UTC/random run directory named `YYYYMMDDThhmmssZ-xxxxxxxx`, an empty confined `events.jsonl`, and an immutable `manifest.json`. It never constructs or reopens an `EventJournal`: the empty journal is created once through the already-open run-directory descriptor with `O_EXCL|O_NOFOLLOW`, `0600`, file `fsync`, and directory `fsync`; the runtime retains only immutable relative-path metadata. The manifest is likewise written descriptor-relatively with no-follow exclusive creation, file/directory `fsync`, `0600` permissions, and a strict size limit. Before any manifest pathname is created, its raw snapshot input is duplicate-key-safe standard JSON parsed, required to exactly equal its canonical reserialization, checked against the exact sealed schema and supplied run/config identity/global readonly fields, then SHA-256 hashed from those canonical bytes. This prevents a run-path replacement after descriptor open from splitting journal and manifest across directories. It records schema/version, run/config identity, UTC creation time, `REAL_ACTIVE=false`, `authorization=NONE`, `field_validation=NOT_ASSERTED`, the raw sealed snapshot, and its SHA-256. It contains no secrets. A collision, existing journal/manifest, malformed/noncanonical/mismatched snapshot, malformed config, relative root, or any symlink fails closed; the partial run is retained for audit and is never resumed or replaced.

The only ROS graph registration is one bounded publisher (`queue_size=1`) for `std_msgs/String` at exactly `/raicom/mission/snapshot`. It publishes a pure, bounded compatibility bridge of the sealed snapshot (`mode`, `state`, `task`, referee/safety state, queues/reasons, and capability source/mode/verification/authorization) required by the existing state-server consumer. End-to-end compatibility is accepted for state-server normalized ingestion and read-only HMI presentation/logging; neither consumer has a control path. The complete raw sealed snapshot remains authoritative in the canonical confined `manifest.json` beside the empty `events.jsonl`; the bridge does not replace either audit artifact. It has no subscribers, services, action clients, shell/subprocess calls, Gazebo calls, or device publishers.

Snapshots state `REAL_ACTIVE=false`, `authorization=NONE`, `task_result=NOT_REAL_SUCCESS`, `real_availability=REAL_UNAVAILABLE`, and `field_validation=NOT_ASSERTED`. Concrete immutable semantic provenance is `navigation=FAKE/DISABLED`, `perception=REPLAY/REPLAY`, and `manipulation=FAKE/DRY_RUN`; every capability is structurally non-actuating, HW-unverified, and never authorizes promotion.

In line with ADR-001 provenance, the fixed bounded snapshot includes a canonical SHA-256 `config_digest` globally and per capability, plus sealed `adapter_identity`, verification and authorization references, and a freshness decision. Perception additionally reports replay mapping digest, bounded relative development `model_path`, model SHA-256, and model verification status. These fields are nonsecret provenance only: they do not upgrade verification or authorization. Runtime configuration copies and freezes the replay class mapping at validation, so mutation of a source dictionary or public metadata cannot change backend behavior. The public runtime surface exposes immutable metadata and `snapshot_json` only; it never starts, assigns, steps, recovers, aborts, or resets a mission.
